Style
REST/JSON on .NET/WCF (XML via Accept: text/xml; JSON default)
Base URL
https://www.wsdot.wa.gov/ferries/api/{vessels|terminals|schedule|fares}/rest
Auth
?apiaccesscode=<API_KEY> query param; free email registration; no documented expiry; currently 200 without it, 400 if present-but-wrong (probed 2026-07-24)
Rate limit
undocumented; no limit headers observed (n=54 spaced calls, 2026-07-24)
Updates
vessellocations + terminalsailingspace ~5 s (docs); alerts event-driven; dims on cacheflushdate; schedules/fares republished per season
History
vesselhistory: data at 2002-03-01, no earlier probe attempted - floor at or before 2002-03 (measured 2026-07-24); all other feeds current/forward-only; past TripDates 400

Quirks & Limitations

Ordered by severity: BLOCKER capability cannot be built as assumed · CORRUPTING silently wrong data unless handled · MINOR keep in mind.

BLOCKERPast schedule and fare dates are unqueryable schedule /schedule, /validdaterange; fares /*

Tested — Requested /schedule/2030-01-01/5 (out of range) and read validdaterange on both sub-APIs (2026-07-24).

Result — 400 with Message: 'valid range begins with today's date (7/23/2026) and extends to the end of the most recently posted schedule (12/26/2026)'. Both windows: 2026-07-23 through 2026-12-26.

So-what — The API never serves a past planned schedule or fare table. Any planned-vs-actual or fare-history capability exists only if consumers snapshot /schedule/{date} and the fares tables while they are current.

BLOCKERterminalsailingspace is current-state only, empties overnight, and covers only some terminals terminals /terminalsailingspace

Tested — Fetched the full collection twice overnight (00:45 and 00:55 PT, 2026-07-24); read the WCF help schema; prior daytime observation of coverage could not be re-verified at this hour.

Result — Both calls returned [] (2 bytes). Docs mark the feed ~5 s fresh. A prior daytime check found only ~6 of 20 terminals reporting (unverified 2026-07-24).

So-what — Drive-up capacity data cannot be assumed to exist for every terminal or any past moment. History requires polling snapshots during service hours, and consumers need an explicit 'this terminal does not report space' state.

CORRUPTINGvesselhistory ids do not join anything - use the vessel name vessels /vesselhistory

Tested — Joined 148 Tacoma history rows (2026-07-17..07-24, fetched 2026-07-24) to vesselbasics on VesselId and on Vessel; called bare /vesselhistory.

Result — VesselId match 0% (history carries 1077/1088 for Tacoma; the dimension says 32). Vessel name match 100% (n=148). Bare /vesselhistory returns one all-null row per vessel in a third id space (Spokane=21, 'WallaWalla'=22).

So-what — Any pipeline keyed on VesselId silently drops every history row. Join on the display name and discard VesselId at ingest.

CORRUPTINGvesselhistory terminals are slip names, not terminal names vessels /vesselhistory; schedule /sailings

Tested — Joined history Departing/Arriving to terminalbasics.TerminalName (n=148, 2026-07-24); inspected sailings TerminalTimes.TerminalBriefDescription.

Result — 0% direct match: history says 'Colman' and 'Bainbridge'; dims say 'Seattle' and 'Bainbridge Island'. Sailings stops carry the same slip vocabulary with TerminalID attached ('Colman P52', TerminalID 7).

So-what — Grouping history by terminal requires a slip-alias mapping; TerminalBriefDescription pairs slip text with TerminalID and is the natural seed. Unmapped slips will appear as other vessels/routes are pulled.

CORRUPTINGSeason stop times ride a 1900-01-01 Pacific sentinel schedule /sailings, /timeadj

Tested — Decoded TerminalTimes.Time across all 90 stop rows and TimeToAdj across all 108 adjustments (2026-07-24).

Result — 90/90 and 108/108 values decode to 1900-01-01 (e.g. /Date(-2208940200000-0800)/ = 1900-01-01 05:30 PST). /schedule/{date} Times carry real dated timestamps instead.

So-what — These fields are time-of-day only. Naive datetime use puts sailings 126 years in the past and breaks any comparison against real dates; extract the time and attach service dates, or use /schedule/{date}.

CORRUPTINGTerminal 122 (Eagle Harbor yard) exists in realtime feeds but no dimension vessels /vessellocations; terminals /*

Tested — Enumerated TerminalIDs across all terminals operations and compared with vessellocations.DepartingTerminalID (2026-07-24 00:55 PT).

Result — terminals ops serve exactly 20 ids (1-22 minus 2 and 6, no 122). 3 of 21 vessels (Sealth, Walla Walla, Tokitae) sat at DepartingTerminalID=122 with InService=false. Join rate 86% (n=21).

So-what — Inner joins silently drop laid-up vessels and FK constraints reject their rows; consumers must handle id 122 (synthetic dimension row or explicit at-yard state).

CORRUPTINGterminalwaittimes looks live but is static boilerplate terminals /terminalwaittimes

Tested — Exploded WaitTimes for all 20 terminals and profiled WaitTimeLastUpdated (21 rows, 2026-07-24).

Result — Every row carries one of exactly two stamps: 2020-08-18 12:31 or 2025-08-18 12:31 PT. Text is arrive-early advice per route, not a measurement.

So-what — Presenting this as a current wait time is silently wrong by up to six years. There is no live wait-time data anywhere in this API.

CORRUPTINGOut-of-service vessels keep stale position timestamps vessels /vessellocations

Tested — Profiled TimeStamp across the 21-row snapshot (2026-07-24 00:55 PT).

Result — In-service vessels: stamps within ~1 minute of fetch. Out-of-service vessels: stamps up to 46 days old (2026-06-08 on a 07-24 fetch). VesselWatchMsg simultaneously reported a VesselWatch outage.

So-what — A map that trusts row presence draws ghost ferries; the truth of a marker is TimeStamp, which must be staleness-filtered.

CORRUPTINGAlert route ids exceed the date-scoped route list schedule /alerts, /routes/{TripDate}

Tested — Exploded AffectedRouteIDs from 9 active alerts and joined to routes/{2026-07-24} (10 rows).

Result — 62% match (n=21 ids). Misses are Fauntleroy/Vashon/Southworth triangle-leg ids (13, 14, 15, 29) that the date-scoped route list does not carry that day; schedroutes across seasons lists 15 route instances.

So-what — Validating alert FKs against routes/{today} silently discards alerts for exactly the disrupted legs; validate against the season-wide route set.

CORRUPTINGfarelineitemsverbose is index-linked, not row-shaped fares /farelineitemsverbose

Tested — Flattened the {TripDate} payload: TerminalComboVerbose[38], LineItemLookup[38], LineItems (27 inner lists), RoundTripLineItems (27) (2026-07-24).

Result — Combos share price lists: 38 lookups point into 27 unique inner arrays; resolving through LineItemLookup yields 770 one-way rows. Zipping the outer arrays by position would misprice 11 of 38 combos.

So-what — Always resolve combos to items through LineItemLookup indices; positional joins silently attach wrong fare tables.

CORRUPTINGUnknown query params pass silently; bad path values return empty 200s all sub-APIs

Tested — Three separate probes (2026-07-24): vesselbasics with bogusparam=zzz; vesselhistory with vessel name 'NotAVessel'; fares terminalcombo with non-adjacent pair 7-8.

Result — bogusparam: 200 with byte-identical payload (9,201 B). NotAVessel: 200 with []. Non-adjacent pair: 400 with Message. Out-of-range TripDate: 400 with Message.

So-what — A typo in a parameter NAME returns unfiltered data that looks correct; a typo in a vessel name looks like an empty history. Validate inputs client-side and alarm on unexpected emptiness rather than retrying.

CORRUPTINGThe server's day boundary lags midnight schedule /validdaterange, /schedule

Tested — Read validdaterange and triggered the out-of-range error message at 00:47 PDT on 2026-07-24.

Result — The error named 'today's date (7/23/2026)' and DateFrom decoded to 2026-07-23 - the server still considered the previous day current almost an hour after local midnight.

So-what — Client-side 'today' and server 'today' disagree in the first hour(s) after midnight; date-keyed requests and rollover logic must tolerate both dates being valid.

MINORAccess code is optional today but rejected when wrong all sub-APIs (except cacheflushdate, which never needs it)

Tested — Three auth probes on vesselbasics (2026-07-24): registered code, parameter entirely absent, and a well-formed but unregistered GUID (all-zeros).

Result — Registered: 200. Absent: 200 with identical payload. Unregistered GUID: 400 with a registration-pointer Message.

So-what — Enforcement machinery exists and could be switched on; always send the key and treat 400+Message as the auth-failure signature (there is no 401/403).

MINORvesselhistory is absent from the official docs vessels /vesselhistory

Result — The operation exists only in the WCF help index; the docs page lists every other vessels operation but not this one. Depth verified to 2002-03 (n=186 for one week) and same-night freshness (00:15 sailing present in a 00:45 fetch).

So-what — The deepest data in the source has no documented contract: no deprecation promise, no schema notes. Consumers should archive what they pull and monitor for drift.

MINORvesselhistory windows can be legitimately empty mid-range vessels /vesselhistory

MINORHTML lives inside text fields fares /farelineitems*; terminals /terminalbulletins, /terminaltransports; schedule /alerts, route notes

Result — Fare labels embed anchor tags (e.g. the Senior/Disability line), bulletins and notes are HTML fragments, alerts carry both HTML and plain-text variants.

So-what — Strip or sanitize before display or SMS/push; prefer the plain-text alert fields (RouteAlertText) where they exist.

MINORVessel dimensions arrive as text with foot/inch marks vessels /vesselstats, /vesselverbose

Tested — Profiled Beam/Draft/Length across 21 vessels (2026-07-24).

Result — Values like "328' 2\"" (Length), "78' 8\"" (Beam), "16' 7\"" (Draft) - strings, not numbers.

So-what — Cast before arithmetic; naive numeric parsing fails or truncates at the foot mark.
